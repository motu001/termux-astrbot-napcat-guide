# 安全与故障排查

## 不要公开哪些信息

- QQ 账号/扫码二维码/验证码、NapCat WebUI Token、OneBot Token、AstrBot 管理密码、模型 API Key。
- SSH 私钥、公网/内网敏感地址、个人私有镜像仓库及备份、原始日志、录屏中的通知和聊天内容。
- 账号口令**由你在自己的设备上设置或从该次启动日志中私下获得**。本仓库没有通用密码。初始密码/Token 一旦泄露就轮换。

管理页默认只能在手机本机或通过 SSH 回环转发访问。若必须开放给可信局域网，优先限制到手机当前 Wi-Fi IP 与受信网段，设置强密码，确认防火墙/路由器**没有公网转发、UPnP 或隧道**，离开该网络时撤销。HTTP 明文管理页不适用于不可信 Wi-Fi。OneBot 端口通常仅服务间访问，别把它当网页或开放公网。

## 常见问题

| 现象 | 先做什么 |
| --- | --- |
| `proot-distro install ubuntu:24.04` 不支持 | 更新 Termux 软件包、看 `proot-distro --help` 和上游 README；**不要 reset 现有环境**。 |
| `uv sync` / Python 版本错误 | 在 Ubuntu 查 `python3 --version`、`uname -m`；按 AstrBot 官方源码指南核对 Python >=3.12 和 ARM64 依赖。 |
| NapCat 安装器下载失败/QQ 不兼容 | 检查官方安装器仓库、最新 issue 和 Linux QQ ARM64 版本；不要执行不明来源脚本。 |
| 手机自己能开，电脑打不开 | 电脑与手机是否同一可信 Wi-Fi？`sshd` 是否启动？SSH 用户名、IP、端口是否来自自己的设备？检查转发窗口有无断线和浏览器地址是不是电脑的 `127.0.0.1`。 |
| WebUI 可达却 QQ 不回复 | 依次核验 QQ 已登录、NapCat 的 WS **客户端**已启用、WS 地址与 AstrBot 监听端口一致、两端 Token 一致、AstrBot 日志有真实连接，然后用另一测试号发消息。 |
| 重启后没起来 | 手机先手动恢复两服务，检查 Android 自启动/后台省电限制，再检查自己编写的开机脚本日志。手动启动通过不等于冷启动通过。 |
| 页面出现两个 NapCat | 核对网址对应端口、实例启动日志、PID 与配置路径；可能是本机转发与局域网入口指向同一服务，也可能是两个实例。**不要凭页面相似就删目录**。 |

## 备份和版本

升级前停服务并备份你自己的 AstrBot `data`、NapCat 配置和必要的会话状态（不要提交到 GitHub）。记录版本、架构、你自己设置的端口和恢复命令；恢复时不要用新默认配置覆盖旧数据。不要将未审查的私有 Docker 镜像、尤其是 AMD64 运行层直接当作 ARM64 手机安装包。
