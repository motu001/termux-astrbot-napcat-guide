# 从零安装与连接（新手机通用路线）

> **阅读前提**：截至 2026-09-25，以下“干净新机”路线参考上游文档，**尚未在全新设备逐行端到端复现**；手机型号、系统、省电策略和上游软件版本不同会改变结果。不要把示例端口当成别人手机当前真实端口。命令分“Termux 外层”和“Ubuntu 内层”，切勿混用。

## 1. 安装 Termux 和 Ubuntu PRoot

从 [Termux 官方仓库的安装说明](https://github.com/termux/termux-app#installation)选择与已有插件相同签名来源安装。打开 Termux，看到 `$` 后逐行输入：

```sh
pkg update && pkg upgrade
pkg install proot-distro openssh curl git
uname -m
proot-distro install ubuntu:24.04
proot-distro login ubuntu
cat /etc/os-release
```

`uname -m` 应符合你设备的 ARM64/AArch64 架构；`/etc/os-release` 显示 Ubuntu。若你的 `proot-distro` 版本不识别 `ubuntu:24.04`，先看它的 `--help` 和[官方 README](https://github.com/termux/proot-distro#quick-start)，别直接执行 `reset/remove`（它们会清数据）。`exit` 回到 Termux，Ubuntu 内包管理用 `apt`，Termux 外层用 `pkg`。

## 2. 在 Ubuntu 安装 AstrBot

以下命令在 **Ubuntu 内**执行。AstrBot 官方源码指南要求 Python **>=3.12**；先检查软件包是否满足，再安装 uv。安装器属于上游可执行脚本，建议先查看内容和上游更新记录；以下是官方 uv 安装方式，下载后自行确认再运行，不使用匿名镜像源。

```sh
apt update
apt install -y python3 python3-venv git curl ca-certificates
python3 --version
curl -LsSf https://astral.sh/uv/install.sh -o /tmp/install-uv.sh
less /tmp/install-uv.sh
sh /tmp/install-uv.sh
. "$HOME/.local/bin/env"
mkdir -p "$HOME/bots" && cd "$HOME/bots"
git clone https://github.com/AstrBotDevs/AstrBot.git
cd AstrBot
uv sync
uv run main.py
```

若缺 `less`，可用 `sed -n '1,200p' /tmp/install-uv.sh` 阅读，或 `apt install -y less`。如果 `python3 --version` 低于 3.12，**不要跳过检查**，改按[官方 AstrBot 源码文档](https://docs.astrbot.app/deploy/astrbot/cli.html)与 uv 指南安装适合本架构的 Python。编译依赖、网络或插件可能使 `uv sync` 失败；看错误而不是反复删目录。首次启动日志会给管理页地址和**随机初始密码**，只在私下保存并立即修改。上游示例 WebUI 常用 `127.0.0.1:6185`，**以你自己的启动日志为准**。保持当前终端打开；新开一个 Termux 会话进行下一步。

## 3. 安装 NapCat（走官方 Termux 路线）

在**新的 Termux 外层会话**操作，**不要在已经登录的 Ubuntu 内执行安装器**。NapCat 官方文档给出 Termux 安装器，它可能创建并管理自己的 Debian/PRoot 运行环境；这与第 2 步 Ubuntu 是**不同**的用户态目录，但网络仍在同一手机上。先看官方项目的最新[Termux 安装步骤](https://napneko.github.io/guide/boot/Shell)及[安装器仓库](https://github.com/NapNeko/NapCat-Installer)，尤其是当日未解决的下载/兼容问题。建议下载脚本后查看再运行。**仅限新安装**：这个上游脚本会创建 `napcat` PRoot 别名，初始化失败时会删除该别名；已有 NapCat 实例/数据者不要直接重跑。脚本内部还会下载并执行另一份 `install.sh`，应一并审查，不要把第一份脚本的阅读当成整个安装链已审核：

```sh
mkdir -p "$HOME/bots" && cd "$HOME/bots"
curl -fL https://raw.githubusercontent.com/NapNeko/NapCat-Installer/main/script/install.termux.sh -o napcat.termux.sh
less napcat.termux.sh
bash napcat.termux.sh
```

若 `less` 不存在，运行 `pkg install less`。**不要**用“curl | bash”绕过审查。官方安装器和 Linux QQ 版本会更新、下载链接可能失效；若报错，优先在安装器仓库的 issue/文档确认，不要安装来历不明的旧恢复包或把电脑的 AMD64 QQ 二进制搬到手机。安装器结束后请**按照它当次实际打印的启动命令**启动 NapCat，而不是猜固定路径。找到自己的 WebUI 地址及登录 Token（通常由启动日志或本地配置给出）；不要截图/上传 Token。本人用测试 QQ 扫码登录并完成验证。

> 另一条路线是在 Ubuntu PRoot 内装 Linux ARM64 QQ + NapCat Shell，但其包、脚本、无 root 权限与 QQ 版本要求更容易变化。本文选官方 Termux 安装器为新机入口；它**不是**原机私有镜像迁移的复刻。

## 4. 用 OneBot 反向 WebSocket 连起来

1. 在 AstrBot WebUI 左侧“机器人”→“创建机器人”→“OneBot v11”。启用，取一个 ID。**仅同机连接时优先把反向 WS 监听主机设为 `127.0.0.1`**（若该版不允许或连接失败，依官方配置临时用 `0.0.0.0`，但须限制访问，绝不要做公网映射），示例端口 `6199`。Token 若配置则两端必须一致。
2. 在 NapCat WebUI “网络配置”→“新建”→“WebSockets 客户端”，启用并填 **`ws://127.0.0.1:6199/ws`**；这不是 NapCat WebUI 地址。保存，按界面要求重连/重启。不要误建成 WebSocket 服务端。
3. 去 AstrBot“数据与日志”找 `aiocqhttp(OneBot v11) 适配器已连接`。它只证明协议连接，不证明 QQ 已登录，更不证明 AI 已回复。
4. 在 AstrBot 按[官方模型接入文档](https://docs.astrbot.app/use/agent-runner.html)选择你自己的模型服务，私下填自己的 Key，设置默认模型/执行器。不要写进公开 JSON、截图、终端历史或视频。不同模型服务可能收费。
5. 用**另一测试 QQ**发一条普通消息：看 NapCat 登录状态、AstrBot 接收/处理日志，核对回复来自期望账号且时间/内容匹配。要宣传“AI 回复已成功”，还必须另验所选模型确实生成了该条回复；规则或插件回复不等于 AI 回复。

## 5. 电脑管理（可选，推荐 SSH 转发）

先在 Termux 外层自行配置 SSH 公钥或私下运行 `passwd`，然后 `sshd`。**Termux 的 SSH 用户名由你手机上 `whoami` 输出决定，不存在通用账号密码**；常见监听端口 8022，但也以自己的设置为准。手机查 Wi-Fi IPv4 地址，不要把它固定写成别人的地址。电脑终端示例（替换尖括号；注意 `127.0.0.1` 是电脑本机）：

```sh
ssh -p 8022 -N -L 127.0.0.1:16185:127.0.0.1:6185 -L 127.0.0.1:16099:127.0.0.1:6099 <Termux用户名>@<手机局域网IP>
```

此命令假设你的 AstrBot 和 NapCat WebUI 分别使用 6185、6099；按自己的**日志实际端口**改。转发后电脑浏览器访问 `http://127.0.0.1:16185/` 和 `http://127.0.0.1:16099/`。SSH 断开只会断电脑入口，不等于停手机服务。若 WebUI 在某个 PRoot 环境未侦听回环，先在手机确认它的实际监听地址，再排错。不要把 QQ/OneBot 或管理页暴露公网。

## 6. 重启和自启

**先手动恢复，最后才谈开机自启**。手机重启后打开 Termux：运行 `sshd`（如需远程管理）；另开 Ubuntu 会话执行 `cd ~/bots/AstrBot && uv run main.py`；依第 3 步安装器当次给出的命令启动 NapCat；再验证 QQ 登录与 OneBot 连接。Termux 会话退出、Android 省电杀后台、网络换址都会影响运行。

Termux:Boot/系统自启动权限和免电池限制因安装来源/系统而不同。不要复制他人的开机脚本：先备份，再按自己实际路径编写幂等启动脚本；**必须真实重启一次、检查日志与回复，才能打勾“自动恢复”**。本仓库未包含可直接套用的自启脚本。
