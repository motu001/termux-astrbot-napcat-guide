# 手机从零部署 QQ 对话机器人：Termux + AstrBot + NapCat

> 面向没有镜像、没有服务器、第一次用 Termux 的读者。2026-09-25 核对官方资料；**本页是通用新装路线，不是对一部全新手机成功复现的保证或实机录像**。原机主的私有镜像仅用于理解架构，**全程不需要下载、登录或恢复该私有镜像**。遇到报错请在当前关卡停下，不要跳过。
>
> **风险提示：** NapCat 是非官方 QQ 协议端，可能因 QQ 更新而失效或带来账号风控；只用自己的测试号。若不接受，改用 [AstrBot 的 QQ 官方机器人接入](https://docs.astrbot.app/platform/qqofficial.html)（需要遵循该平台申请流程）。下面的 OneBot 路线不等于 QQ 官方接入。

## 先选好路线和准备物品

只需一台支持 ARM64 的 Android 手机（本机示范机型红米 K40 Gaming）、稳定网络、**建议**至少 8 GB 空闲空间和充电器；另备一个测试 QQ 号、一个可扫码的设备或本机扫码办法。如果想让 AI 自由对话，还需自行合法取得模型服务商的 API Key。电脑、root、Docker、私有仓库和别人制作的镜像都**不需要**。手机里的“Ubuntu／Debian”是 PRoot 用户态环境，不是刷机。

**操作约定：** 一个代码块一次复制；先看块上标注的终端。出现 `$` 一般在 Termux；`root@...` 一般在 Ubuntu 或 Debian，拿不准就运行 `cat /etc/os-release`。每完成一个✅再继续。不要录入或公开 QQ 二维码、WebUI Token、OneBot Token、API Key。手机浏览器访问 `127.0.0.1` 指的是**这部手机自己**。

```text
Android 手机
 ├─ Termux：安装器、tmux 会话
 ├─ Ubuntu PRoot：AstrBot（面板通常 127.0.0.1:6185）
 └─ Debian PRoot：NapCat + QQ Linux（WebUI 通常 127.0.0.1:6099）
    NapCat ──反向 WebSocket──> AstrBot（127.0.0.1:6199/ws）
```

### 第 1 关｜装好 Termux 和官方 Ubuntu

1. 从 [Termux GitHub Releases](https://github.com/termux/termux-app/releases) 或 [F-Droid](https://f-droid.org/en/packages/com.termux/)安装；不要混用来源不一致的 Termux/插件。第一次打开等待初始化，在 Termux **主界面**逐块执行：

```sh
pkg update -y && pkg upgrade -y
pkg install -y proot-distro tmux curl
uname -m
```

✅ ARM64 手机上应看到 `aarch64`。若不是，先确认架构，不要把 ARM64 下载文件照搬过去。

2. 仍在 **Termux 主界面**，安装官方 Ubuntu 容器：

```sh
proot-distro install ubuntu:24.04
proot-distro list
proot-distro login ubuntu
cat /etc/os-release
```

✅ 最后一条能看到 Ubuntu 信息，说明进入 Ubuntu。这里的 `ubuntu:24.04` 是 PRoot-Distro 支持的**官方发行版镜像标签**，不是机主私有镜像。若 Docker Hub 下载中断，先检查网络和可用空间，参考 [PRoot-Distro 官方文档](https://github.com/termux/proot-distro#readme)排查；不要去随机网盘找“整合镜像”，也不要把程序的 Release 附件误当系统 rootfs。**已安装成功不要重复 install。**

### 第 2 关｜在 Ubuntu 里装 AstrBot

以下代码都在 **Ubuntu** 的 `root@...` 提示符运行：

```sh
apt update
apt install -y curl ca-certificates python3 git
python3 --version
curl -LsSf https://astral.sh/uv/install.sh -o /tmp/install-uv.sh
sed -n '1,80p' /tmp/install-uv.sh
sh /tmp/install-uv.sh
export PATH="$HOME/.local/bin:$PATH"
uv tool install astrbot --python 3.12
astrbot init
astrbot run
```

`uv` 安装器来自 Astral；不放心先对照[官方安装文档](https://docs.astral.sh/uv/getting-started/installation/)。`astrbot init` **只在首次初始化执行一次**，之后启动只执行 `astrbot run`。`uv` 安装版应在命令行更新，不要从 WebUI 做版本升级。手机 ARM64＋PRoot 并非 AstrBot 保证兼容的平台；依赖编译、内存或网络报错要保留无密钥日志，不要宣称“安装成功”。

✅ 看启动日志中的面板地址，在**同一手机**的浏览器打开 `http://127.0.0.1:6185/`（以实际日志端口为准）。首次用户名/随机密码按当次日志提示，立即自行修改。页面打不开：先看 `astrbot run` 的终端有没有退出；不要把面板映射到公网。**保持这个运行 AstrBot 的窗口，不要按 Ctrl+C 或在里面输入 `exit`。** 下一关从 Termux 左侧边缘向右滑，点 **NEW SESSION（新建会话）**，在新窗口继续。

### 第 3 关｜官方 Debian 容器里装 NapCat（不是装进 Ubuntu）

在刚打开的 **Termux 新会话**中执行（不是运行 AstrBot 的 Ubuntu 窗口）。先运行 `pkg --version`：能显示版本，才说明回到 Termux；若出现 `pkg: not found`，说明进错窗口，请新开 Termux 会话，不要结束 AstrBot。然后执行：

```sh
proot-distro install debian:stable --name napcat
proot-distro list
proot-distro login napcat
cat /etc/os-release
```

✅ 看到 Debian 信息；这只代表容器建好，**不是 QQ 已经可用**。若下载中断，同第 1 关检查网络、存储和官方文档，不要临时改用来路不明的 Debian 包。

以下在 **Debian** 中：

```sh
apt-get update
apt-get install -y sudo curl ca-certificates
curl -fL https://raw.githubusercontent.com/NapNeko/NapCat-Installer/main/script/install.sh -o /root/NapCat-install-linux.sh
sed -n '1,100p' /root/NapCat-install-linux.sh
bash /root/NapCat-install-linux.sh --docker n --cli n --proxy 0
```

这里直接下载 **NapCat 官方安装脚本**和 QQ Linux 官方 ARM64 包；`--docker n` 避免在无 root 的 PRoot 中硬装 Docker。安装器内容或参数可能变化，执行前对照[官方仓库](https://github.com/NapNeko/NapCat-Installer)。**只有安装器明确显示安装完成，且 QQ 可启动，才能打勾。**看到 `NoSuchKey`、403、`dpkg-deb: not a Debian format archive`、架构不符时停止；不要把错误页当 `.deb`，更不要改用来历不明的 QQ 包。此项曾在测试网络碰到官方包访问失败，不能保证每部手机都一次成功。

✅ 按**当次安装器输出**的启动命令启动 NapCat，常见形式如下；不要机械照抄旧版本的 QQ 绝对路径：

```sh
xvfb-run -a /安装器显示的/QQ/qq --no-sandbox
```

> 上一行的 `/安装器显示的/QQ/qq` 是**占位文字，不能原样执行**。若安装器没有显示启动路径，先查看它末尾的 `启动 Napcat` 提示；不要猜测目录。另开 Termux 会话继续后续操作，勿关闭运行 NapCat 的终端。

### 第 4 关｜QQ 登录和两边 WebUI

在手机浏览器打开 NapCat 启动日志给出的 WebUI 地址（常见 `http://127.0.0.1:6099/`，**以当次日志为准**）。WebUI Token 按安装器提示**私下**查看，登录 QQ 的二维码由本人扫码完成。不要拍进视频。确认 NapCat 页面显示 **QQ 已在线**。这一步没有通过，先不要设置 OneBot。

✅ 到此你应能同时打开 AstrBot 面板和 NapCat WebUI；能打开面板**不等于** QQ 在线，QQ 在线**不等于**机器人能回复。

### 第 5 关｜反向 WebSocket：先 AstrBot，再 NapCat

1. AstrBot 面板 → **机器人** → **创建机器人** → **OneBot v11**。启用；反向 WebSocket **监听主机地址**可按官方示例填写 `0.0.0.0`、端口 `6199`；确认手机可信网络且不要路由器端口转发到公网。只有两端在同一手机、版本允许本地监听时，可优先尝试绑定 `127.0.0.1`。Token 可在两端设置相同的私密随机串。保存。
2. NapCat WebUI → **网络配置** → **新建** → **WebSockets 客户端**（不是服务端）：

```text
ws://127.0.0.1:6199/ws
```

启用，按需填写和 AstrBot **完全相同**的 Token，保存。`6099` 是 NapCat 面板，`6185` 是 AstrBot 面板，**不是** OneBot 目标；`/ws` 不能漏。两容器在同一手机共享网络栈。若 QQ 登录或两边进程没保持运行，连接会断。

✅ AstrBot → **数据与日志 → 日志**应看到 `aiocqhttp(OneBot v11) 适配器已连接`。只证明协议连接，还不等于能收发或调用模型。官方步骤见 [AstrBot OneBot v11 接入文档](https://docs.astrbot.app/platform/aiocqhttp.html)。

### 第 6 关｜接入模型，另号真实测试

想让机器人**用 AI 回复**，在 AstrBot → **模型提供商**选择你的服务商；按其官方控制台填写 Base URL（如果需要）、API Key 和**真实模型 ID**，保存、测试模型成功后，到当前**配置文件 → AI 配置 → 对话模型**选中它并保存。具体字段以[官方模型文档](https://docs.astrbot.app/providers/start.html)和当次 WebUI 为准，别把别人的 Key/URL 抄进来。

用**另一个 QQ 号**向机器人号发一条无隐私的测试消息；依次检查：

| ✅ 关卡 | 应看到的结果 | 没看到先查 |
|---|---|---|
| 面板 | 同一手机能打开 AstrBot 和 NapCat WebUI | 进程是否还在、端口/日志 |
| 登录 | NapCat 页面 QQ 在线 | 本人扫码和账号状态 |
| 连接 | AstrBot 日志“适配器已连接” | `6199/ws`、Token 和两端进程 |
| 回复 | 另号收到回答；AstrBot 日志有消息事件和模型调用 | 触发规则、模型测试、额度和日志 |

**“收到回复”不必然是 AI 生成。**要证明 AI，还要看模型测试/调用记录和回复路径。所有示意聊天截图都只能作为“应看到什么”的参考，不是本机这次新装的成功录像。

### 第 7 关｜保活、重启和常见错误

Android 设置中为 Termux 允许后台运行、取消省电限制，插电并保持网络。首装时前面开出的两个 Termux 窗口是前台会话，**不属于 tmux，不能用 attach 找回**。若以后选择用 `tmux` 分别保持进程，旧会话存在时才用 `tmux attach -t astrbot` / `tmux attach -t napcat`；**不要在不同会话里反复启动同一实例**。例如手机重启、确认原进程均已结束后，**手动**恢复 AstrBot：

```sh
# Termux 主界面，确认没有现存 astrbot 会话后
termux-wake-lock
tmux new -s astrbot
proot-distro login ubuntu
export PATH="$HOME/.local/bin:$PATH"
astrbot run
```

在这个会话内按 `Ctrl+B`、松开按 `D` 可分离。NapCat 同理在另一 tmux 会话内进入 `napcat` 容器、用**安装器当次给出的** QQ 启动命令。开机自启不是这一串命令自动提供的；重启后要重新检查 QQ 登录和 OneBot 连接，**不能承诺无人值守自动上线**。手机不是高可靠服务器。

| 现象 | 检查 |
|---|---|
| `pkg: not found` | 你在 Ubuntu/Debian；`exit` 回 Termux。 |
| `apt-get: command not found` | 先运行 `cat /etc/os-release` 核对所在环境；不要靠这一条报错判断是在 Termux 还是容器。 |
| `astrbot: not found` | Ubuntu 内先执行 `export PATH="$HOME/.local/bin:$PATH"`。 |
| `6185` 打不开 | AstrBot 进程、日志、实际端口。 |
| `6099` 打不开 | NapCat/QQ 启动日志、安装是否真正完成。 |
| 能打开两面板但不回复 | 依序查 QQ 在线 → 反向 WS 已连接 → 模型测试 → 真实消息日志。 |
